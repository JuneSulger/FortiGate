Introduction — comprendre le FortiGate

Le FortiGate est un pare-feu nouvelle génération (NGFW) de Fortinet : il ne se contente pas de filtrer des ports, il inspecte le trafic en profondeur (applications, contenu, menaces) tout en gérant le routage, le VPN, l'identité des utilisateurs et le WiFi. Ce document explique chaque grand menu de son interface (GUI), avec les notions à connaître et des cas d'usage concrets pour chacun.

Ce guide est théorique : il est pensé pour comprendre à quoi sert chaque menu et comment raisonner face à un scénario, sans nécessiter d'accès pratique au boîtier.

Un firewall, plusieurs métiersFiltrage réseau, VPN, contrôle applicatif, antivirus, authentification et supervision cohabitent dans le même boîtier.
GUI et CLITout ce qui se fait dans le GUI a un équivalent en CLI (ligne de commande) ; le GUI reste la porte d'entrée la plus lisible pour apprendre.
FortiOS, un même OS partoutDu petit boîtier de succursale au firewall de datacenter, c'est le même système d'exploitation qui tourne, avec les mêmes menus.

Organisation d'un FortiGate

Avant d'entrer dans les menus, quelques notions structurantes reviennent partout :

  • VDOM — un FortiGate physique peut être découpé en plusieurs pare-feux virtuels indépendants, chacun avec ses propres politiques, interfaces et administrateurs.
  • Interfaces et zones — chaque port physique ou logique (VLAN, tunnel VPN...) reçoit un rôle ; les zones regroupent plusieurs interfaces pour simplifier l'écriture des règles.
  • Politique de pare-feu — la brique centrale : elle décide quel trafic est autorisé, entre quelles zones, avec quelle inspection de sécurité.
  • FortiGuard — le service cloud qui alimente en continu les signatures antivirus, IPS, catégories web et réputation, sans lesquelles les profils de sécurité seraient rapidement obsolètes.
À retenir

Le réflexe pour comprendre n'importe quel menu FortiGate : se demander s'il configure la structure (interfaces, routage), la règle (policy), l'inspection (security profile), l'identité (utilisateur) ou la supervision (log/monitor).

Menu 01

Dashboard & Monitors

Le tableau de bord est la première chose que l'on voit après connexion : une vue d'ensemble de l'état de santé et de l'activité du boîtier, avant même de toucher à une configuration.

Les dashboards

  • Status — vue générale : CPU, mémoire, sessions actives, licences, informations système.
  • Security — menaces détectées récemment par les security profiles (antivirus, IPS, web filter).
  • Network — état des interfaces, tables de routage statique/dynamique, moniteurs IPsec et SSL-VPN.
  • Assets &amp; Identities — inventaire des appareils et utilisateurs détectés sur le réseau.
  • WiFi — état des FortiAP connectés et de leurs clients, si un contrôleur WiFi est actif.

Chaque dashboard est composé de widgets déplaçables et configurables : on peut construire un tableau de bord sur mesure pour surveiller ce qui compte réellement pour un site donné.

FortiView

FortiView regroupe des vues analytiques qui répondent à une question précise sur le trafic : quelles sont les sessions en cours, quelles applications consomment le plus de bande passante, quelles sources génèrent le plus de trafic, quels sites web sont les plus visités.

Explication simple

FortiView croise les logs de trafic en temps réel ou sur une période choisie, pour transformer des lignes de logs en une vue lisible : tableau trié, graphique, carte.

Cas d'usage

Un administrateur remarque un ralentissement réseau. Il ouvre FortiView &gt; Sources et trie par bande passante consommée : il identifie en quelques secondes le poste ou l'application responsable, sans avoir à fouiller les logs bruts.

À retenir

Le Dashboard répond à « comment va le boîtier maintenant ? », FortiView répond à « qui fait quoi sur le réseau ? ». Les deux sont des outils de lecture, pas de configuration.

Menu 02

Network

Le menu Network définit la structure : comment le FortiGate se connecte physiquement et logiquement au reste du réseau, avant même de parler de règles de sécurité.

Interfaces

  • Interface physique — un port RJ45/SFP auquel on attribue un rôle (LAN, WAN, DMZ) et un mode d'adressage (statique, DHCP client, PPPoE).
  • VLAN — sous-interface qui segmente un port en plusieurs réseaux logiques isolés.
  • Zone — regroupement de plusieurs interfaces sous un même nom pour simplifier les policies.
  • Aggregate (LACP) — plusieurs ports physiques combinés en un seul lien logique, pour la bande passante et la redondance.
  • Virtual wire pair — mode transparent qui insère le FortiGate dans un lien existant sans changer l'adressage IP, souvent utilisé pour un déploiement en coupure minimalement intrusif.
Explication simple

Une interface est le point d'entrée/sortie du trafic ; tout le reste (routage, policy, NAT) s'appuie sur les interfaces et zones définies ici.

Cas d'usage

Un site a un seul port WAN mais trois réseaux internes (bureaux, WiFi invité, caméras). On crée trois VLAN sur le port LAN, chacun avec son propre sous-réseau, puis on les regroupe en zones pour écrire des policies distinctes plus lisibles.

Services réseau de base

DNS

Résolution de noms : le FortiGate peut relayer vers des serveurs externes ou agir lui-même comme serveur DNS.

DHCP

Serveur ou relais DHCP pour attribuer automatiquement des adresses IP aux clients d'un VLAN.

Routage statique

Route configurée manuellement, indiquant la passerelle pour atteindre une destination.

Routage dynamique

OSPF, BGP ou RIP pour propager automatiquement les routes entre équipements.

Proxy explicite / transparent

Le client pointe volontairement vers le FortiGate comme proxy, ou le trafic est intercepté sans configuration côté client.

SD-WAN

Regroupe plusieurs liens WAN et choisit dynamiquement le meilleur chemin selon des règles de performance (SLA).

Notions avancées, en bref

Ces sujets sont davantage rencontrés en environnement multi-sites ou opérateur, mais il est utile de savoir les situer :

NotionEn une phrase
SD-WANUtilise plusieurs liens WAN (Internet, MPLS, LTE) en simultané et bascule automatiquement selon la qualité mesurée par des sondes Performance SLA.
ADVPNExtension d'IPsec qui laisse deux sites spoke négocier un tunnel direct plutôt que de toujours transiter par le hub central.
ZTNAVérifie l'identité et la conformité de chaque appareil avant chaque accès applicatif, plutôt que de faire confiance à tout ce qui est déjà sur le réseau interne.
VRFIsole plusieurs tables de routage indépendantes sur un même FortiGate, comme des VDOM mais au niveau du routage uniquement.
À retenir

Network répond toujours à une question de structure : par où le trafic entre et sort, et comment il trouve son chemin. La sécurité applicative (policies, profils) vient dans les menus suivants, une fois cette structure posée.

Menu 03

Policy & Objects

C'est le cœur du métier FortiGate : la firewall policy décide, ligne par ligne, quel trafic est autorisé, entre quelles zones, avec quelle inspection. Tout le reste du boîtier existe pour nourrir ou appliquer ces règles.

Firewall policy

Une policy combine toujours les mêmes ingrédients : une interface source, une interface destination, une ou plusieurs adresses source, une ou plusieurs adresses destination, un ou plusieurs services, une action (accept/deny), et éventuellement des security profiles et des règles de NAT.

Explication simple

Les policies sont évaluées de haut en bas : la première règle qui correspond exactement au trafic s'applique, les suivantes sont ignorées pour cette session.

Cas d'usage

Un service web interne doit être accessible depuis le LAN mais pas depuis le WiFi invité. On crée une policy LAN → DMZ autorisant le port 443 vers l'adresse du serveur, et on s'assure qu'aucune policy WiFi invité → DMZ n'existe : par défaut, tout ce qui n'est pas explicitement autorisé est bloqué.

À retenir

L'ordre des policies compte. Une règle trop large placée trop haut peut masquer des règles plus précises placées en dessous — c'est l'erreur de configuration la plus fréquente sur FortiGate.

Variantes de policy

Type de policyRôle
NGFW policyIntègre directement l'inspection applicative (Application Control) dans la règle elle-même, plutôt que via un profil séparé.
Local-in policyContrôle le trafic à destination du FortiGate lui-même (accès au GUI, VPN), distinct du trafic qui ne fait que traverser.
DoS policyApplique des seuils anti-déni de service (limite de connexions ou de paquets) sur une interface.
Access control listFiltrage simple, souvent utilisé en périphérie ou en environnement opérateur.

Objets réutilisables

  • Address object — une IP, une plage, un sous-réseau ou un FQDN nommé, réutilisé dans plusieurs policies.
  • Service object — un protocole et un port nommés (ex. HTTPS = TCP/443).
  • Schedule — une plage horaire d'activation d'une policy (ex. accès Internet limité en dehors des heures de bureau).

Nommer et réutiliser ces objets plutôt que de saisir des adresses brutes dans chaque règle est ce qui rend une configuration FortiGate lisible et maintenable sur la durée.

NAT : SNAT et DNAT

SNAT (Source NAT)DNAT (Destination NAT)
Traduit l'adresse source du trafic sortant, généralement vers l'IP publique du FortiGate.Redirige une IP/port publics vers une ressource interne, via un objet VIP.
Central SNAT centralise les règles dans une table unique appliquée avant les policies.Une VIP peut rediriger un port spécifique (port forwarding) ou répartir la charge entre plusieurs serveurs internes.
Explication simple

Le SNAT permet à un réseau privé de sortir sur Internet via une seule IP publique. Le DNAT fait l'inverse : il expose un service interne à l'extérieur sous une IP publique.

Cas d'usage

Un serveur web interne en 10.0.0.10 doit être joignable depuis Internet. On crée une VIP qui associe l'IP publique du FortiGate au port 443 vers 10.0.0.10:443, puis une policy WAN → LAN qui autorise ce trafic vers la VIP.

Menu 04

Security Profiles

Une firewall policy décide qui a le droit de passer. Les security profiles décident ce qu'on fait du contenu de ce trafic une fois qu'il est autorisé — c'est ce qui transforme un simple pare-feu en NGFW.

Antivirus

Inspecte les fichiers transitant dans le trafic pour détecter des malwares connus, souvent complété par une analyse sandbox pour les menaces inconnues.

Web Filter

Autorise, bloque ou avertit sur l'accès à des sites selon leur catégorie FortiGuard ou une liste explicite.

Application Control

Identifie et contrôle des applications précises (réseaux sociaux, streaming, jeux) indépendamment du port réseau utilisé.

IPS

Détecte et bloque des signatures d'attaques connues (exploits, scans) dans le trafic réseau.

DNS Filter

Filtre les requêtes DNS par catégorie, bloquant la résolution d'un domaine avant même toute connexion.

File Filter

Bloque des transferts de fichiers selon leur type ou extension, indépendamment du contenu inspecté.

SSL Inspection : la condition souvent oubliée

La grande majorité du trafic web actuel est chiffré (HTTPS). Sans déchiffrement, la plupart des security profiles ne voient qu'un flux chiffré illisible et ne peuvent pas vraiment inspecter le contenu.

Mode certificateMode deep inspection
Inspecte seulement le nom de domaine du certificat (SNI).Déchiffre entièrement le trafic pour une inspection complète du contenu.
Léger, peu d'impact, moins de faux positifs.Nécessite de déployer un certificat FortiGate comme autorité de confiance sur les postes clients.
Suffisant pour du filtrage web basé sur la catégorie du site.Indispensable pour qu'Application Control, l'antivirus ou l'IPS inspectent réellement le contenu HTTPS.
Explication simple

Sans SSL Inspection en mode deep, un antivirus ou un IPS ne peut analyser que le trafic non chiffré : la majorité des menaces modernes, transportées en HTTPS, passeraient inaperçues.

Cas d'usage

Une entreprise veut bloquer le téléchargement de fichiers infectés via des sites HTTPS. Il faut activer le profil SSL Inspection en mode deep sur la policy concernée, et déployer le certificat FortiGate sur les postes pour éviter les alertes de sécurité du navigateur.

À retenir

Un security profile n'agit que sur une policy à laquelle il est attaché : créer un profil ne suffit pas, il faut encore l'associer à la bonne règle de pare-feu pour qu'il s'applique.

Menu 05

VPN

Deux familles de VPN cohabitent sur FortiGate, pour deux besoins différents : relier des sites entre eux (IPsec), ou donner un accès distant à des utilisateurs nomades (SSL-VPN).

IPsec — relier des sites

  • Site-to-site — les deux extrémités du tunnel ont une IP publique fixe connue à l'avance ; typique entre un siège et une agence.
  • Dial-up — l'IP du pair distant n'est pas connue à l'avance ; utilisé pour des utilisateurs nomades ou de nombreux sites spoke se connectant à un hub.
  • ADVPN — les sites spoke négocient automatiquement un tunnel direct entre eux plutôt que de toujours transiter par le hub, une fois le trafic identifié comme fréquent.
  • IKE — le protocole qui négocie et authentifie les paramètres du tunnel avant que le trafic chiffré ne circule.
Explication simple

Un tunnel IPsec crée un chemin chiffré entre deux réseaux, comme si les deux sites étaient reliés par un câble privé.

Cas d'usage

Une entreprise a un siège et trois agences. Elle configure un hub IPsec au siège, et un tunnel dial-up depuis chaque agence vers le hub : chaque agence peut atteindre les ressources du siège, chiffrées de bout en bout, sans dépendre d'une IP fixe côté agence.

SSL-VPN — accès distant utilisateur

Mode tunnelMode web
Nécessite un client (FortiClient) installé sur le poste.Accessible depuis un simple navigateur, sans rien installer.
Donne un accès réseau complet, comme si l'utilisateur était sur place.Limité à des applications web ou des raccourcis prédéfinis (RDP, SSH, partages).
Adapté au télétravail régulier avec un poste géré.Adapté à un accès ponctuel depuis un poste non maîtrisé.
À retenir

IPsec relie des réseaux entre eux (site-à-site) ; le SSL-VPN relie une personne à un réseau (accès distant). Les deux peuvent s'appuyer sur les mêmes objets d'authentification (utilisateurs, groupes, MFA).

Menu 06

User & Authentication

Ce menu répond à la question « qui accède, et comment le prouve-t-il ? ». Une fois l'identité vérifiée, elle peut être utilisée dans les firewall policies pour appliquer des règles selon l'utilisateur plutôt que seulement selon l'adresse IP.

Sources d'identité

  • Utilisateur local — compte créé directement sur le FortiGate, mot de passe stocké localement ; pratique pour un petit nombre de comptes.
  • LDAP — le FortiGate interroge un annuaire existant (souvent Active Directory) pour authentifier sans dupliquer les comptes.
  • RADIUS — authentification centralisée via un serveur externe (NPS, FortiAuthenticator), qui peut aussi pousser des attributs (groupe, VLAN).
  • Groupe d'utilisateurs — regroupement logique référencé directement dans les policies, pour appliquer une règle selon l'identité plutôt que l'adresse IP.
Explication simple

Une identité vérifiée peut devenir un critère de policy au même titre qu'une adresse IP : on peut autoriser un groupe précis à accéder à une ressource, indépendamment de l'endroit du réseau d'où il se connecte.

Cas d'usage

Le service comptabilité doit accéder à une application financière sensible, mais pas le reste de l'entreprise. Plutôt que de filtrer par sous-réseau, on crée un groupe « Compta » synchronisé depuis LDAP et on l'utilise directement comme critère source dans la policy.

Renforcer l'authentification

  • Portail captif — page d'authentification affichée avant d'autoriser l'accès réseau, courante en WiFi invité.
  • MFA / FortiToken — ajoute un second facteur (code à usage unique) en complément du mot de passe, réduisant le risque de compromission.
À retenir

L'authentification répond à « qui êtes-vous ? », la firewall policy qui utilise ensuite ce groupe répond à « qu'avez-vous le droit de faire ? » — une distinction qui rappelle le couple authentification/autorisation que l'on retrouve dans beaucoup d'environnements IT.

Menu 07

WiFi & Switch Controller

Beaucoup de FortiGate agissent aussi comme contrôleur central pour les équipements WiFi et switch Fortinet, évitant une console de gestion séparée pour ces couches.

FortiAP

Point d'accès WiFi Fortinet, découvert et géré directement depuis le FortiGate une fois autorisé.

SSID

Réseau WiFi diffusé, avec son propre chiffrement, VLAN de rattachement et politique d'accès.

FortiSwitch

Commutateur Fortinet géré depuis le FortiGate, avec attribution de VLAN par port centralisée.

Portail invité

SSID dédié avec portail captif, isolé sur son propre VLAN pour ne jamais toucher le réseau interne.

Explication simple

Le FortiGate pousse la configuration (SSID, VLAN, sécurité) vers les FortiAP et FortiSwitch qu'il gère, comme il le ferait pour ses propres interfaces.

Cas d'usage

Un bureau ajoute un réseau WiFi invité isolé. On crée un SSID dédié rattaché à un VLAN spécifique, on le limite par une firewall policy à l'accès Internet uniquement (pas d'accès au LAN interne), et on active un portail captif pour tracer les connexions.

À retenir

Cette centralisation n'est utile que si l'environnement utilise du matériel Fortinet (FortiAP/FortiSwitch) — avec d'autres marques, ce menu reste vide et la gestion se fait depuis leurs propres consoles.

Menu 08

Security Fabric & notions avancées

Un FortiGate isolé protège déjà un réseau. La Security Fabric consiste à le connecter aux autres produits Fortinet pour obtenir une visibilité et une automatisation à l'échelle de toute l'infrastructure.

Security Fabric

  • Elle relie FortiGate, FortiAnalyzer, FortiAP, FortiSwitch, FortiClient et d'autres produits Fortinet dans une topologie partagée.
  • Elle permet de voir, depuis un seul FortiGate racine, l'ensemble des appareils du Fabric et leurs alertes.
  • Security Rating évalue automatiquement la configuration par rapport aux bonnes pratiques Fortinet et propose un score avec des recommandations concrètes.
Explication simple

La Security Fabric transforme des produits individuels en un système qui partage des informations de menace et peut réagir collectivement.

Cas d'usage

Un FortiClient détecte un malware sur un poste. Grâce au Fabric, cette information peut déclencher automatiquement une mise en quarantaine réseau du poste par le FortiGate, sans intervention manuelle.

Automation Stitches

Une Automation Stitch associe un déclencheur (un événement, une alerte, un log précis) à une ou plusieurs actions automatiques : envoyer une notification, exécuter un script, changer une configuration, mettre en quarantaine un appareil.

Cas d'usage

Déclencheur : un compte administrateur échoue à se connecter 5 fois de suite. Action : envoi automatique d'un e-mail à l'équipe sécurité. Cela évite de devoir surveiller les logs manuellement pour détecter ce type d'événement.

API REST

Le FortiGate expose une API REST qui permet d'automatiser sa configuration et sa supervision depuis un script ou un outil tiers (inventaire, provisioning automatisé, intégration avec un SOC), plutôt que de tout faire manuellement via le GUI.

VDOM, en détail

Un Virtual Domain (VDOM) permet de faire fonctionner plusieurs pare-feux logiquement indépendants sur un seul boîtier physique, chacun avec ses propres interfaces, politiques et parfois ses propres administrateurs.

Sans VDOMAvec VDOM
Une seule table de politiques pour tout le boîtier.Une table de politiques distincte par VDOM.
Simple à administrer pour un site unique.Utile pour un hébergeur ou une entreprise qui isole plusieurs clients/filiales sur un même boîtier.
Pas de séparation administrative possible.Chaque VDOM peut avoir ses propres administrateurs, limités à leur périmètre.
Menu 09

System

Le menu System regroupe tout ce qui concerne l'administration du boîtier lui-même, plutôt que le trafic qui le traverse.

Administrateurs et accès

  • Chaque compte administrateur a un profil d'accès qui définit précisément ce qu'il peut voir et modifier.
  • Un hôte de confiance (trusted host) restreint les adresses IP autorisées à se connecter avec un compte donné, réduisant la surface d'attaque du management.
  • Feature Visibility affiche ou masque des menus entiers selon les fonctionnalités réellement utilisées, pour garder une interface plus simple.

Haute disponibilité (HA)

Le FGCP (FortiGate Clustering Protocol) regroupe deux boîtiers ou plus en cluster pour assurer la continuité de service si l'un tombe en panne.

Actif-PassifActif-Actif
Un seul boîtier traite le trafic à la fois ; le second prend le relais en cas de panne.Les deux boîtiers traitent le trafic simultanément, avec répartition de charge.
Configuration la plus courante et la plus simple à raisonner.Utile quand la capacité de traitement d'un seul boîtier ne suffit plus.
Explication simple

En HA, la configuration est synchronisée automatiquement entre les membres du cluster : modifier une policy sur l'un la propage sur l'autre.

Cas d'usage

Un site critique ne peut pas tolérer de coupure réseau. Deux FortiGate identiques sont montés en cluster actif-passif : si le boîtier actif tombe en panne matérielle, le second prend le relais en quelques secondes, sans intervention manuelle.

Maintenance courante

  • Firmware — mise à jour de la version de FortiOS, à planifier en tenant compte des notes de version et de la compatibilité HA.
  • Certificats — gestion des certificats utilisés pour le GUI, le SSL-VPN ou la SSL Inspection.
  • SNMP — permet une supervision de l'état du boîtier par un outil de monitoring tiers.
  • Backup / Restore — sauvegarde et restauration du fichier de configuration, essentielle avant tout changement important.
À retenir

Toujours sauvegarder la configuration avant une mise à jour de firmware ou un changement de structure important (VDOM, HA) : c'est le filet de sécurité le plus simple et le plus souvent oublié.

Menu 10

Log & Report

Toute décision prise par le FortiGate — trafic autorisé, menace bloquée, connexion VPN — peut être journalisée. Ce menu permet de consulter ces traces et d'en tirer des rapports.

Où stocker les logs ?

Stockage localFortiAnalyzer
Disque du FortiGate lui-même, capacité limitée.Solution centralisée dédiée, pour un ou plusieurs FortiGate.
Suffisant pour un petit site ou une rétention courte.Nécessaire pour une rétention longue, de la corrélation ou des rapports poussés.

Types de logs

  • Traffic log — chaque session traitée par les firewall policies, avec la règle qui l'a autorisée ou bloquée.
  • Logs de sécurité — événements générés par les security profiles (menace antivirus détectée, site bloqué par le web filter, signature IPS déclenchée).
  • Logs système — événements d'administration, de HA, de mise à jour.
Explication simple

Le traffic log est souvent le premier réflexe de diagnostic : il montre exactement quelle policy a traité une connexion, et pourquoi elle a été acceptée ou refusée.

Cas d'usage

Un utilisateur signale ne plus accéder à une application interne. On filtre le traffic log sur son adresse IP et le port concerné : le log montre une session bloquée par une policy précise, ce qui confirme immédiatement l'origine du problème.

Outils de diagnostic

  • Packet capture — enregistre les paquets bruts transitant sur une interface, pour une analyse fine d'un problème réseau.
  • Debug flow (CLI) — trace en temps réel le traitement d'un paquet à travers le routage, le NAT et les policies, très utile pour comprendre pourquoi un trafic est bloqué de façon inattendue.
À retenir

Log & Report répond après coup à « que s'est-il passé ? », alors que FortiView (dans Dashboard & Monitors) répond en temps réel à « que se passe-t-il maintenant ? ». Les deux s'appuient sur les mêmes données de trafic.

Synthèse

Révision et cas pratique transverse

Ce dernier chapitre ne présente plus de nouveau menu ; il relie les briques entre elles sur un scénario complet, et propose une méthode pour raisonner face à n'importe quel besoin.

Méthode pour aborder un scénario FortiGate

  • 1. Structure — quelles interfaces, zones et routes sont concernées ?
  • 2. Règle — quelle firewall policy doit exister, avec quelle source, destination et service ?
  • 3. Inspection — quels security profiles doivent être attachés à cette policy (antivirus, web filter, IPS...) ?
  • 4. Identité — le trafic doit-il être limité à des utilisateurs ou groupes précis ?
  • 5. Preuve — comment vérifier que ça fonctionne (traffic log, FortiView, packet capture) ?
À retenir

Ces cinq questions, dans cet ordre, permettent de retomber sur ses pieds face à n'importe quel scénario FortiGate : structure, règle, inspection, identité, preuve.

Mini-cas de synthèse

Cas fil rouge : une PME avec un siège et une agence, un accès télétravail, et un WiFi invité.

BesoinRéponse FortiGate
Relier le siège et l'agence en permanenceTunnel IPsec site-to-site entre les deux FortiGate.
Permettre le télétravail depuis des postes personnelsSSL-VPN en mode web pour un accès applicatif limité, ou mode tunnel pour les postes gérés par l'entreprise.
Isoler le WiFi invité du réseau interneSSID dédié sur un VLAN séparé, avec portail captif et policy limitée à l'accès Internet uniquement.
Bloquer les menaces dans le trafic webSecurity profiles (Antivirus, Web Filter, IPS, Application Control) attachés aux policies concernées, avec SSL Inspection en mode deep.
Limiter l'accès à l'application financièreGroupe d'utilisateurs synchronisé via LDAP, utilisé comme critère source dans une policy dédiée.
Garder une trace en cas d'incidentEnvoi des logs vers FortiAnalyzer et consultation du traffic log en cas de doute.
Explication simple

Aucune de ces briques ne fonctionne isolément : une policy sans security profile laisse passer du contenu non inspecté ; un security profile sans SSL Inspection ne voit rien du trafic HTTPS ; un groupe d'utilisateurs non référencé dans une policy n'a aucun effet.

Cas d'usage

Sur ce mini-cas, l'ordre logique de configuration serait : d'abord les interfaces et VLAN (structure), puis les tunnels VPN, puis les policies avec leurs objets, puis l'attachement des security profiles, et enfin la vérification via les logs.

Pour continuer

  • Reliez toujours un menu à la question à laquelle il répond, plutôt que de le mémoriser isolément.
  • Le GUI et le CLI décrivent la même configuration : consulter l'équivalent CLI d'une action GUI aide à mieux comprendre ce qui se passe réellement.
  • La documentation officielle Fortinet (docs.fortinet.com) reste la référence à jour pour toute version précise de FortiOS.

Glossaire

Les 75 termes techniques du document, classés par ordre alphabétique. Chaque occurrence de ces termes dans le corps du texte est un lien qui renvoie directement ici.

Address object
Objet nommé représentant une IP, une plage, un sous-réseau ou un FQDN, réutilisable dans les policies.
Administrateur
Compte disposant d'un profil d'accès (permissions) pour se connecter et gérer le FortiGate, avec des restrictions possibles par hôte de confiance.
ADVPN
Auto-Discovery VPN : extension d'IPsec qui permet à deux sites spoke de négocier automatiquement un tunnel direct plutôt que de passer par le hub.
Aggregate
Regroupement de plusieurs interfaces physiques en un seul lien logique (LACP), pour la bande passante et la redondance.
Antivirus
Profil qui inspecte les fichiers transitant dans le trafic pour détecter des malwares connus, souvent complété par l'analyse sandbox.
API REST
Interface de programmation qui permet d'automatiser la configuration et la supervision du FortiGate depuis un script ou un outil externe.
Application Control
Profil qui identifie et contrôle des applications spécifiques (réseaux sociaux, streaming, jeux) indépendamment du port utilisé.
Automation Stitch
Règle qui associe un déclencheur (événement, log, alerte) à une ou plusieurs actions automatiques (notification, script, changement de config).
Backup / Restore
Sauvegarde et restauration du fichier de configuration du FortiGate (au format texte ou chiffré).
BGP
Protocole de routage dynamique utilisé entre systèmes autonomes, très employé pour le SD-WAN et les connexions multi-opérateurs.
Central SNAT
Table unique et centralisée de règles SNAT, appliquée avant les policies de pare-feu plutôt que dans chaque règle individuellement.
CLI
Interface en ligne de commande du FortiGate, accessible via SSH, console série ou le widget CLI Console dans le GUI.
Dashboard
Page d'accueil du GUI, composée de widgets configurables donnant une vue d'ensemble de l'état du boîtier.
Debug flow
Outil CLI qui trace en temps réel le traitement d'un paquet à travers les différentes étapes internes du FortiGate (routage, NAT, policy).
DHCP
Service qui attribue automatiquement une adresse IP aux clients d'un réseau ; le FortiGate peut être serveur DHCP ou relais vers un serveur externe.
DNAT
Destination NAT : redirige une IP/port publics vers une ressource interne, typiquement via un objet VIP.
DNS
Service de résolution de noms ; le FortiGate peut agir comme serveur DNS, relais, ou forwarder conditionnel.
DNS Filter
Profil qui filtre les requêtes DNS par catégorie, bloquant la résolution de domaines indésirables avant même la connexion.
DoS policy
Règle qui applique des seuils anti-déni de service (limitation de connexions/paquets) sur une interface.
Feature Visibility
Paramètre qui affiche ou masque des menus entiers du GUI selon les fonctionnalités réellement utilisées, pour simplifier l'interface.
File Filter
Profil qui bloque des transferts de fichiers selon leur type ou leur extension, indépendamment du contenu.
Firewall policy
Règle qui autorise ou bloque un trafic entre deux zones/interfaces, selon la source, la destination, le service et l'heure — le cœur de la configuration FortiGate.
Firmware
La version installée de FortiOS sur le boîtier ; sa mise à jour corrige des failles et ajoute des fonctionnalités.
FortiAnalyzer
Solution centralisée de collecte de logs et de reporting pour un ou plusieurs FortiGate.
FortiAP
Point d'accès WiFi Fortinet, géré directement depuis le FortiGate (contrôleur WiFi intégré).
FortiCare
Compte Fortinet utilisé pour enregistrer un boîtier, gérer les licences et accéder au support.
FortiGuard
Service cloud de Fortinet qui fournit les signatures et catégories utilisées par les security profiles (antivirus, IPS, web filtering...), mis à jour en continu.
FortiManager
Solution centralisée de gestion de configuration pour administrer plusieurs FortiGate depuis une seule console.
FortiOS
Le système d'exploitation qui fait tourner tous les FortiGate — c'est lui qui définit les menus, les commandes CLI et les fonctionnalités disponibles.
FortiSwitch
Commutateur Fortinet, géré directement depuis le FortiGate (contrôleur switch intégré) pour une administration centralisée.
FortiView
Ensemble de vues analytiques en temps réel et historiques : sessions, applications, menaces, sources/destinations les plus actives.
Groupe d'utilisateurs
Regroupement logique d'utilisateurs (locaux ou distants) référencé dans les policies pour appliquer des règles selon l'identité.
GUI
Interface graphique web du FortiGate, accessible via un navigateur (HTTPS sur le port de management).
HA
High Availability : regroupement de deux FortiGate ou plus en cluster (FGCP) pour assurer la continuité de service en cas de panne d'un boîtier.
Hôte de confiance
Adresse IP ou plage depuis laquelle un compte administrateur est autorisé à se connecter, pour limiter la surface d'attaque du management.
IKE
Internet Key Exchange : protocole qui négocie et authentifie les paramètres de sécurité d'un tunnel IPsec.
Interface
Port physique ou logique du FortiGate (LAN, WAN, VLAN, tunnel...) auquel on attribue une adresse IP et un rôle.
IPS
Intrusion Prevention System : profil qui détecte et bloque des signatures d'attaques connues dans le trafic réseau.
IPsec
Protocole de VPN standard utilisé pour chiffrer des tunnels site-à-site ou dial-up entre le FortiGate et un autre équipement.
LDAP
Protocole d'annuaire (souvent Active Directory) utilisé par le FortiGate pour authentifier des utilisateurs existants sans les recréer localement.
Local-in policy
Règle qui contrôle le trafic à destination du FortiGate lui-même (management, VPN), distincte des policies de trafic traversant.
Log
Enregistrement d'un événement (trafic, sécurité, système) horodaté, stocké localement ou envoyé vers FortiAnalyzer.
MFA / FortiToken
Authentification à plusieurs facteurs ; FortiToken est l'application ou le jeton matériel Fortinet qui génère le code à usage unique.
NGFW policy
Mode de politique où l'inspection applicative (Application Control) est directement intégrée à la règle de pare-feu, plutôt qu'associée séparément.
OSPF
Protocole de routage dynamique à état de liens, utilisé pour propager automatiquement les routes au sein d'un réseau interne.
Packet capture
Outil de diagnostic qui enregistre les paquets bruts transitant sur une interface, pour analyser un problème réseau en détail.
Performance SLA
Sonde SD-WAN qui mesure en continu la latence, la gigue et la perte de paquets d'un lien pour décider s'il respecte le seuil de qualité défini.
Policy route
Route qui dirige le trafic selon des critères (source, port, interface entrante) plutôt que selon la seule destination.
Portail captif
Page d'authentification affichée automatiquement avant d'autoriser l'accès réseau, courante en WiFi invité.
Proxy explicite
Mode où le client est configuré pour envoyer son trafic web volontairement vers le FortiGate en tant que proxy.
Proxy transparent
Mode où le FortiGate intercepte le trafic web sans configuration côté client.
RADIUS
Protocole d'authentification centralisée, souvent utilisé avec un serveur NPS ou FortiAuthenticator pour valider les identifiants et pousser des attributs.
Rapport
Document généré automatiquement à partir des logs, résumant l'activité réseau ou de sécurité sur une période donnée.
Route statique
Route de réseau configurée manuellement, indiquant la passerelle à utiliser pour atteindre une destination donnée.
Schedule
Objet définissant une plage horaire pendant laquelle une policy est active.
SD-WAN
Fonctionnalité qui regroupe plusieurs liens WAN (Internet, MPLS, LTE) et choisit dynamiquement le meilleur chemin selon des règles de performance.
Security Fabric
Architecture qui connecte plusieurs produits Fortinet (FortiGate, FortiAnalyzer, FortiAP, FortiSwitch, FortiClient...) pour partager visibilité et automatisation.
Security profile
Profil d'inspection (antivirus, web filter, IPS...) attaché à une firewall policy pour inspecter le contenu du trafic autorisé.
Security Rating
Évaluation automatique de la configuration du FortiGate par rapport aux bonnes pratiques Fortinet, avec un score et des recommandations.
Service object
Objet nommé représentant un protocole et un port (ex. HTTPS = TCP/443), réutilisable dans les policies.
SNAT
Source NAT : traduit l'adresse IP source du trafic sortant, généralement vers l'IP publique du FortiGate.
SSID
Nom du réseau WiFi diffusé, configuré avec son propre chiffrement, VLAN et politique d'accès.
SSL Inspection
Déchiffrement du trafic HTTPS pour permettre aux profils de sécurité d'inspecter son contenu, en mode certificate (léger) ou deep (complet).
SSL-VPN
VPN d'accès distant basé sur SSL/TLS, utilisable en mode tunnel (client complet) ou web (portail navigateur).
Traffic log
Journal qui enregistre chaque session ou connexion traitée par les firewall policies, avec la policy qui l'a autorisée ou bloquée.
Utilisateur local
Compte défini directement sur le FortiGate, avec mot de passe stocké localement.
VDOM
Virtual Domain : partition logique d'un FortiGate physique en plusieurs firewalls virtuels indépendants, chacun avec ses propres politiques et interfaces.
VIP
Virtual IP : objet qui associe une adresse publique à une adresse interne, avec ou sans redirection de port, pour exposer un service interne.
Virtual wire pair
Association de deux interfaces en mode transparent (bump-in-the-wire), sans routage, pour insérer le FortiGate sans changer l'adressage existant.
VLAN
Sous-interface qui segmente un port physique en plusieurs réseaux logiques isolés, identifiés par un tag 802.1Q.
VPN dial-up
Configuration IPsec où l'adresse IP du pair distant n'est pas connue à l'avance (utilisateurs nomades, sites multiples).
Web Filter
Profil qui autorise, bloque ou avertit sur l'accès à des sites selon leur catégorie ou une liste explicite.
Widget
Petit module d'information ajouté à un dashboard (CPU, licences, top menaces, etc.).
Zone
Regroupement de plusieurs interfaces sous un même nom, pour simplifier l'écriture des politiques de pare-feu.
ZTNA
Zero Trust Network Access : modèle d'accès qui vérifie l'identité et l'état de conformité de chaque appareil avant chaque connexion à une application, plutôt que de faire confiance au réseau.
